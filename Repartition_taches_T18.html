Plan de Répartition des Tâches & Solution aux Déséquilibres

Projet T18 — HomeService : FasoSkills · Advanced Mobile Development (Dr Lebian Wilfried NIKIEMA)
Document officiel en français · Analyse des lacunes et rééquilibrage de l'équipe

🚨 Le Problème Majeur Identifié dans la Répartition Actuelle :

  • 1. Le cœur de l'application est orphelin côté Backend : Cédric a fait le Frontend Client et Agent, et Aman a fait le Frontend Admin et le Backend uniquement Admin. Qui fait le Backend Client et Agent ? Le module de recherche d'artisans, les demandes de travaux (`jobRequests`), la soumission des devis (`quotes`), l'acceptation unique d'un devis et les avis vérifiés (`reviews`) ne peuvent pas être laissés à l'abandon !
  • 2. Le piège du barème de Dr NIKIEMA (Facteur individuel = 0) : Le professeur a écrit noir sur blanc : « Chaque membre doit écrire du code sur l'API ET sur l'application mobile ». Si Cédric ne présente aucun code Backend lors de la soutenance, ou si Aman ne présente aucun code sur l'application Client/Agent, le jury va sanctionner individuellement.
  • 3. Déséquilibre massif de charge : Cédric a pris en charge plus de 80% du Frontend mobile (10+ écrans Flutter complets), pendant qu'Aman s'est limité à la seule administration.

✅ La Solution de Rééquilibrage Stratégique :

Pour combler les trous sans repartir de zéro et garantir la note maximale à chacun :

  • AMAN DOIT ÉTENDRE SON BACKEND : Aman ne doit pas faire uniquement l'Admin. En tant que lead Backend, il doit finaliser le Backend métier : les Demandes (`jobRequests`), les Devis (`quotes`) et les Avis (`reviews`) avec les règles de sécurité BOLA imposées par Dr Nikiema.
  • CÉDRIC PREND LE BACKEND TEMPS RÉEL (WEBSOCKETS) : Pour avoir son quota obligatoire de code Backend, Cédric prend la responsabilité du serveur WebSocket et de la messagerie instantanée (`api/src/modules/chat/` et `ws-server.ts`), ce qui s'aligne parfaitement avec l'écran de chat qu'il a déjà codé sur Flutter (Fonctionnalité Avancée = 5 points au barème).
  • PRISCA & GRACE (si présentes dans le groupe) : Prennent en charge les tests automatisés (Supertest API + BLoC tests), la recette métier, la documentation (Design Doc M1, Rapport M4) et la préparation des slides de soutenance.
